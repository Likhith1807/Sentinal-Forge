**Runbook – Detection of Repeated Failed Sign‑ins**  
Ticket: INC-52427 | Severity: medium | Analyst: R. Ibarra  

**Trigger:** Repeated failed authentication attempts against **svc‑deploy30** on **CITRIX‑GW‑03** that later succeed.

**Required fields:** Pull **account_id**, **event_type**, and **timestamp** from the authentication log. The **auth_method** field is present but must not be used in the rule logic.

**Steps**

1. Query the authentication log for records where **event_type** = “failed” for a given **account_id**.  
2. Identify any sequence where the same **account_id** registers **no fewer than 4** failed events within a rolling window of **30 seconds**.  
3. Verify that the next record for that **account_id** within the same window shows a successful sign‑in.  
4. If the pattern is met, generate an alert and tag the source subnet **10.14.127.0/24** for further investigation.  

**Notes:** The detection does not consider **auth_method**; it is only logged for reference. Ensure the alert includes the original **timestamp** values for audit.
