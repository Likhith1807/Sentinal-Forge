# Service Account svc-sync12 Used an Unexpected Method

Summary

Per policy, svc-sync12 should only ever authenticate with a certificate. A successful login for svc-sync12 was recorded on MAIL-GW-19 using token instead. The affected subnet is 10.157.81.0/24.

Detection follow-up

The rule should fire when a successful sign-in uses a different authentication method than the account's expected one. The rule reads `account_id`, `event_type`, `auth_method` and `expected_auth_method` from the authentication log.
